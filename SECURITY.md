# Security Policy

This policy applies to all repositories in the Niobe Labs organization.

## Reporting a vulnerability

Please report security vulnerabilities privately — do **not** open a public
issue for them.

- Use [GitHub private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability)
  ("Report a vulnerability" under the affected repository's **Security** tab), or
- email the maintainers at **security@niobe-labs.example** (replace with your
  team's real contact before publishing).

Please include a description of the issue, steps to reproduce, affected
repository and versions, and any potential impact. We aim to acknowledge
reports within a few business days and will keep you updated on remediation
progress.

Please give us a reasonable window to release a fix before any public
disclosure.

## Supported versions

Most Niobe Labs repositories are libraries or service templates consumed at
the latest commit on their default branch — security fixes are made there,
and consumers should update to pick them up. A repository that ships tagged
releases with a longer support window will document its own supported-version
table in its README.
